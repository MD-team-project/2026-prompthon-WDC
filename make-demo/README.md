# 발표 덱

브라우저에서 슬라이드처럼 넘기는 **단일 HTML 발표 자료**. PPT 변환 없이 그대로 발표한다.

디자인은 메인 앱(`packages/frontend/src/styles.css`)의 토큰과 형태를 그대로 쓴다.
슬라이드 골격(고정 캔버스 · 상하단 바 · 목차 · 키보드 네비)은 `html-presentation`
스킬 방식을 따른다.

---

## 파일

| 파일 | 무엇 |
|---|---|
| `deck.html` | **발표 자료 본체.** 이걸 열고, 이걸 고친다 |
| `INSTRUCTIONS.md` | AI 에이전트용 편집 규칙. 발표자가 읽을 필요는 없다 |
| `COMPONENTS.md` | 쓸 수 있는 컴포넌트 사전. 어떤 형태가 가능한지 궁금할 때 본다 |
| `examples/sample-5min.html` | 프롬프트 한 번으로 채운 **작동 예시**. 어떤 결과가 나오는지 먼저 열어보면 빠르다 |
| `scripts/pull-characters.mjs` | FE 캐릭터 아트를 덱으로 가져온다 |
| `scripts/build-single-file.mjs` | 이미지까지 합쳐 배포용 단일 파일을 만든다 |
| `assets/` | 가져온 이미지가 쌓이는 곳 (처음엔 비어 있다) |

`deck.html` 은 **빈 스켈레톤으로 유지**한다. 실제 작업은 이걸 복사해서 하거나,
그냥 `deck.html` 을 채우고 필요하면 git 으로 되돌린다.

---

## 발표자 사용법

### 1. 열어보기

`deck.html` 을 브라우저로 그냥 열면 된다. 서버가 필요 없다.

| 키 | 동작 |
|---|---|
| `←` `→` `Space` | 이동 |
| `F` | 전체화면 |
| `Home` `End` | 처음 / 끝 |
| `Esc` | 목차 닫기 |

우상단 **목차** 버튼으로 원하는 슬라이드로 점프한다.

### 2. 내용 채우기 — 프롬프트로 시킨다

직접 HTML 을 고치지 않아도 된다. **하고 싶은 말을 그대로 말하면 된다.**
에이전트가 `INSTRUCTIONS.md` 규칙에 따라 `deck.html` 을 고친다.

프롬프트 예시:

> make-demo 폴더의 발표 덱을 채워줘. 5분 발표고, 우리 팀은 LG 제품에 AI 캐릭터를
> 붙이는 서비스를 만들었어. 문제는 ThinQ 가 설정 화면 덩어리라 아무것도 학습하지
> 않는다는 거고, 우리 차별점은 캐릭터가 사용 기록에서 스스로 스킬을 발견한다는 거야.
> 기술은 EXAONE 으로 발견을 돌리고 Bedrock 으로 제어해. 마지막에 라이브 시연 예고
> 슬라이드 하나 넣어줘.

이렇게만 말하면 슬라이드 수를 정하고, 컴포넌트를 배정하고, 목차까지 맞춰서 채워준다.

**부분 수정도 된다.**

> 3번 슬라이드가 너무 빽빽해. 둘로 쪼개줘.
> 차별점 슬라이드를 좌우 대조 형태로 바꿔줘.
> 표지 제목을 "캐릭터가 제품을 배운다" 로 바꾸고 팀명은 WDC 로.
> 기술 슬라이드에 근거 출처 칩 3개 붙여줘.

### 3. 캐릭터 아트 넣기 (선택)

기본 상태에는 이미지가 없다. 캐릭터를 쓰고 싶으면 먼저 가져온다.

```bash
node make-demo/scripts/pull-characters.mjs
```

무엇이 있는지 먼저 보려면:

```bash
node make-demo/scripts/pull-characters.mjs --list
```

`make-demo/assets/characters/` 로 복사되고, 그 다음부터 에이전트에게 "표지에 안마의자
캐릭터 넣어줘" 처럼 말하면 된다.

> 실제 제품 사진은 넣지 않는다. 이 서비스에서 제품의 UI 는 캐릭터이고, 기기 사진을
> 붙이면 그 논지가 흐려진다.

### 4. 발표 당일 — 단일 파일로 굳히기

```bash
node make-demo/scripts/build-single-file.mjs
```

`make-demo/dist/deck-standalone.html` 이 나온다. 이미지가 파일 안에 들어가 있어서 USB
로 옮기거나 다른 PC 에서 열어도 깨지지 않는다.

폰트는 CDN 이라 **네트워크가 없으면 시스템 폰트로 대체된다.** 레이아웃은 유지되지만
글자 모양이 달라지므로, 발표장 네트워크가 불안하면 미리 한 번 확인한다.

## 발표 전 점검

- [ ] 발표장 프로젝터에서 한 번 띄워본다. 해상도는 자동으로 맞지만 **색은 눈으로 봐야 안다**
- [ ] `F` 로 전체화면이 되는지
- [ ] 목차 점프가 전부 맞는지
- [ ] 잘린 슬라이드가 없는지 (`INSTRUCTIONS.md` 의 검증 스니펫)
- [ ] 시간을 재본다. 장당 30~45초가 적정
- [ ] 단일 파일 버전을 만들어 USB 에 넣어둔다

## 알아두면 좋은 것

**고정 캔버스.** 내용은 1660×934 (16:9) 안에서 만들어지고, JS 가 화면 크기에 맞춰
통째로 확대·축소한다. 4K 든 노트북이든 항상 한 화면에 꽉 찬다. 브라우저 줌
(`Ctrl` `+`) 은 쓰지 않아도 된다 — 창 크기에 자동 반응하는 게 정상이다.

**제품별 색.** 슬라이드에 `data-product="massagechair"` 같은 속성이 붙으면 그
슬라이드의 강조색이 바뀌고, 상단바·목차 틴트까지 따라간다. 메인 앱과 같은 방식이다.
제품별로 색이 다른 이유가 있으니 임의로 바꾸지 않는 게 좋다.

**세로 스크롤이 없다.** 내용이 캔버스를 넘으면 스크롤이 생기는 대신 **조용히 잘린다.**
그래서 편집 후 검증이 필요하다. 에이전트에게 맡기면 알아서 확인한다.
